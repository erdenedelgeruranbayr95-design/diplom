# Хүн гараар хийх ёстой бүх зүйл — нэгдсэн жагсаалт

> Энэ баримт нь `ROADMAP-7-PHASES.md`-д тэмдэглэгдсэн **бүх ХҮН-шаардсан (код-аар
> хийх боломжгүй) зүйлийг нэг газраас харах боломжтой болгоно** — тус бүрд нь
> дэлгэрэнгүй зааврыг агуулсан баримт руу заана. Мөн дутуу байгаа env хувьсагчдыг
> хаанаас, хэрхэн авахыг нэг доор жагсаав.

---

## 1. Дутуу env хувьсагчид (аль хэдийн `backend/.env`-д бий, зөвхөн 2 зүйл дутуу)

| Хувьсагч | Файл | Одоогийн байдал | Хаанаас авах |
|---|---|---|---|
| `JAMENDO_CLIENT_ID` | `backend/.env` | Хоосон (заавал биш) | https://developer.jamendo.com/v3.0 — үнэгүй бүртгүүлж Client ID авна |
| `SENTRY_DSN` | `backend/.env` | Огт байхгүй (заавал биш) | https://sentry.io — үнэгүй Developer plan, Node.js project үүсгэж DSN авна |

Дэлгэрэнгүй алхам алхмаар заавар: **[`docs/ENV-MISSING-KEYS-GUIDE.md`](./ENV-MISSING-KEYS-GUIDE.md)**
(мөн production-д заавал солих ёстой dev-secret-үүдийн жагсаалт тэнд бий).

## 2. Phase 4 — Capacitor Android бодит build (Android SDK шаардсан)

Код түвшинд **бүрэн бэлдэгдсэн** (`frontend/capacitor.config.ts`, `frontend/android/`,
`HapticWaveformPlugin.java`) — зөвхөн бодит `.apk` build хийгдээгүй, учир нь энэ
хөгжүүлэлтийн орчинд Android SDK/Gradle/Android Studio байхгүй.

**Хийх зүйл:**
1. Android Studio суулгасан компьютер дээр `npm run cap:sync && npm run cap:open`
2. Бодит Android төхөөрөмж/эмулятор дээр `npx cap run android`
3. `pulse(strength, durationMs)`-ийг 0.2/0.5/1.0 `strength`-ээр гараар турших,
   амплитудын ялгаа мэдрэгдэж байгааг баталгаажуулах

Дэлгэрэнгүй: **[`docs/CAPACITOR-ANDROID-SETUP.md`](./CAPACITOR-ANDROID-SETUP.md)**

## 3. Phase 6 — Хэрэглэгчийн туршилт ба гарын шалгалт (бодит хүн шаардсан)

| Зүйл | Тайлбар |
|---|---|
| **SUS сэтгэл ханамжийн оноо** | 10 асуулттай стандарт (Brooke, 1996) санал асуулга, бодит хэрэглэгчийн хариулт шаардана |
| **Сонсголын бэрхшээлтэй 5-10 хүнтэй туршилт** | Дипломын хамгийн хүчтэй нотолгоо — бодит хүний биеийн мэдрэмжийг симуляци хийх боломжгүй |
| **NVDA screen reader-ийн бодит тест** | axe-core зөвхөн статик HTML/ARIA шалгадаг, жинхэнэ дэлгэцгүй navigation flow-г шалгахгүй |
| **Хэмнэл таних нарийвчлал (%)** | Бодит хэрэглэгчийн хариу үйлдэл дээр үндэслэсэн хэмжилт |

Дэлгэрэнгүй асуулга, журам, template: **[`docs/HUMAN-TESTING-PLAN.md`](./HUMAN-TESTING-PLAN.md)**

Автоматаар аль хэдийн хийгдсэн (энэ жагсаалтад ороогүй): Beat detection F-measure,
Latency хэмжилт, WCAG/axe-core автомат audit — бүгд `docs/measurements/`-д бэлэн.

## 4. Phase 5 — Зохиогчийн эрхийн (Takedown) журам

Код биш, **ажлын журам** — нэхэмжлэл ирэхэд хэн, юу, хэдэн цагт хийхийг тодорхойлсон.
Одоо ч бэлэн боловч, **хариуцах хүн(ий нэр/имэйл)-ийг бодитоор томилох** ажил ХҮН
шаардсан (баримт дотор placeholder байдлаар үлдсэн байж болно).

Дэлгэрэнгүй: **[`docs/TAKEDOWN-PROCEDURE.md`](./TAKEDOWN-PROCEDURE.md)**

## 5. Phase 7 — Production дэд бүтэц (домэйн/сервер/мерчант шаардсан)

| Зүйл | Яагаад код-аар хийх боломжгүй |
|---|---|
| Домэйн + DNS | Жинхэнэ домэйн худалдаж авах, DNS A/AAAA бичлэг серверийн IP рүү заах |
| VPS/сервер | Бодит серверийн эзэмшил, SSH хандалт |
| Nginx/Caddy + TLS (Let's Encrypt) | Жинхэнэ домэйн байхгүй тул сертификат авах боломжгүй |
| GitHub Secrets (`SSH_HOST`/`SSH_USER`/`SSH_PRIVATE_KEY`) | Бодит серверийн мэдээлэл шаардана — CI/CD workflow код бэлэн, зөвхөн secret дутуу |
| QPay/SocialPay мерчант эрх | Хуулийн этгээдийн гэрээ, мерчант данс — компанийн бүртгэл шаардана |
| Нэхэмжлэх/буцаалт | QPay/SocialPay-ийн жинхэнэ API-аас хамаарна (мерчант эрхийн дараа) |
| Бодит мөнгөн гүйлгээ туршилт | Бодит данс, бодит мөнгө шаардана |

Дэлгэрэнгүй алхам алхмаар заавар (§1-8 хуваасан): **[`docs/PRODUCTION-DEPLOYMENT-PLAN.md`](./PRODUCTION-DEPLOYMENT-PLAN.md)**

## 6. Phase 1 — Жижиг үлдэгдэл (заавал биш, код-аар хийх боломжтой ч одоогоор орхигдсон)

- Offline fallback: сүлжээгүй үед сүүлийн утгыг кэшлэх (`localStorage`-г кэш болгож,
  эх сурвалж биш) — код-аар хийх боломжтой, гэхдээ хүн шаардсан биш тул энд зөвхөн
  бүрэн байдлын үүднээс дурьдав. Хэрэгжүүлэлт хийгдээгүй.
